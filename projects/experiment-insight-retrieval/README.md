# Project 21: historical-experiment evidence retrieval

**Source test:** [OpenAI Machine Learning Engineer, Core Experimentation](https://openai.com/careers/machine-learning-engineer-core-experimentation-seattle/) asks for cross-experiment learning that retrieves historical results, preserves provenance and permissions, expresses uncertainty, and abstains when evidence is weak. The [employer ATS posting](https://jobs.ashbyhq.com/openai/9d4d2727-27f3-4a63-857c-a96466130645) was last published September 24, 2026 in the October 14 audit; last-published can reflect republication.

Run `python3 insights.py` and `python3 -m unittest test_insights.py` here. A deterministic baseline retrieves matching experiment records by intervention, metric, segment, permission scope, design validity, and freshness. It does not reveal the count or contents of records outside the requested scope. It preserves source/version IDs, synthesizes a fixed-effect estimate from eligible records, and either proposes a **human-reviewed live experiment** or abstains. Tests show a restricted result and invalid or stale records cannot change the proposal, and a conflicting pair causes abstention.

Every experiment, effect, standard error, permission, and source ID is invented. The scope comes from the caller rather than an authenticated identity, so this is **not** a production access-control system. The fixture was designed to show both proposal and abstention. The fixed-effect calculation assumes independent, comparable experiments and does not test heterogeneity or multiple comparisons. No real customer data, LLM synthesis, retrieval model, production rollout, or decision impact is demonstrated. Historical evidence can generate a hypothesis; a new randomized experiment is still needed for causal validation in its target setting.
